# Sprint 4.9 — Uninstall Atomicity And Installer PATH Hardening

## Goal

- Fix uninstall atomicity: defer manifest removal until after all file deletions succeed, report structured rollback/recovery details on partial failure.
- Fix installer PATH: modify install.sh and install.ps1 to add the bin directory to PATH for the current session and shell profile on fresh install, not merely warn.

## Required Work

- Reorder uninstall operations in `src/cmd/uninstall.go`: delete all managed files first, then remove hooks, then remove the manifest record. If any file deletion fails, do not remove the manifest record — instead return a structured error envelope listing which files could not be removed and which remain tracked.
- Update `src/cmd/uninstall_test.go` to reflect the corrected atomicity contract: assert manifest record is preserved when file removal fails, and assert it is removed only after all deletions succeed.
- Modify `scripts/install.sh` to add the selected bin directory to `$PATH` for the current shell session and append the appropriate export line to `~/.bashrc` or `~/.zshrc` on fresh install (detect which shell is active). Do not merely warn — actually modify PATH.
- Modify `scripts/install.ps1` to add the selected bin directory to the user PATH environment variable via `[Environment]::SetEnvironmentVariable` on fresh install, not merely emit a warning.
- Update `tests/installer/test_install.sh` and `tests/installer/test_install.ps1` to remove the pre-seeded PATH setup and verify that a fresh install (no prior PATH entry) results in `sc` being discoverable on PATH after install.
- Add `docs/phase-4/4.8-installer-hardening-and-doc-gaps.md` to the branch (copy from `feature/p4-plan` worktree at `/Users/randlee/Documents/github/synaptic-canvas-dolt-worktrees/feature/p4-plan/docs/phase-4/4.8-installer-hardening-and-doc-gaps.md`).

## Implementation Notes

- Uninstall: the current order is manifest-remove → hook-remove → file-delete. Correct order is file-delete → hook-remove → manifest-remove. Any failure in file-delete must short-circuit and leave the manifest intact.
- For PATH on macOS/Linux: detect active shell via `$SHELL`, append `export PATH="$INSTALL_DIR:$PATH"` to the appropriate rc file. Emit a notice that the user must `source` the file or open a new shell.
- For PATH on Windows: use `[Environment]::SetEnvironmentVariable('PATH', ..., 'User')` to persist. The current session PATH can be updated with `$env:PATH = ...`.
- The installer test changes require running in a temp environment without the bin dir pre-seeded; use a subshell or temp HOME to isolate.

## Non-Goals

- Do not implement full transactional rollback (restoring deleted files). The goal is atomicity of the manifest record relative to actual disk state.
- Do not modify upgrade or install atomicity — those are addressed in Sprint 4.10 if needed.
