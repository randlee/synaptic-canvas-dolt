## Required Work

- Expand `status --json` and `validate --json` so they can confirm scope,
  version, branch, install site, dependency provenance, hook state, and local
  modification inventory after mutations.
- Align snapshot metadata and readback with install records and validation
  output.
- Define the exact file-state vocabulary as `ok`, `modified`, `missing`,
  `unreadable`, and `extra`, and model higher-level failures as typed
  validation items with severities.
- Make `sc snapshot <package>` fail with `ambiguous_target` if the package
  exists in more than one scope and `--scope` is omitted.
- Ensure rollback or partial-failure outcomes are visible in structured
  mutation results or structured error details, not only in logs.
- Ensure `sc scan` fails with typed `validation_failed` when the required
  catalog cache is absent and names `sc catalog update` as the recovery path.
- Use shared DTOs for immediate mutation results and follow-up read commands.
- Add tests that verify post-mutation state through read commands rather than
  by re-deriving state from logs alone.

## Implementation Notes

`status --json` should expose one logical row per package with separate scope
sub-objects so human and AI consumers can reason about local/global coexistence
without diffing two unrelated arrays.

`validate --json` should emit a flat `items` list with explicit `kind`,
`severity`, `state`, and target-identification fields. Do not overload file
state names for dependency or hook problems.

Suggested validation item shape:

```json
{
  "kind": "hook",
  "severity": "error",
  "state": "missing",
  "hook_event": "PreToolUse",
  "message": "tracked hook registration not found"
}
```

## Acceptance Criteria

- `status --json` and `validate --json` are rich enough to confirm mutation
  effects without re-deriving state from logs.
- Readback includes dependency provenance and hook-registration summaries.
- Validation remains list-based and severity-driven in JSON.
- Validation severity vocabulary is fixed to `info`, `warn`, `error`, and
  `critical`.
- Mutation-family tests verify post-mutation state using shared DTOs and read
  commands.
- Snapshot behavior is deterministic in both the single-scope and
  multi-installed ambiguous-target cases.
- `sc scan` returns typed `validation_failed` when the catalog cache required
  for reconciliation is absent.
- Any new JSON fields added for readback, such as `hook_event`, are documented
  in `docs/synaptic-canvas-cli.md` in the same sprint change.
