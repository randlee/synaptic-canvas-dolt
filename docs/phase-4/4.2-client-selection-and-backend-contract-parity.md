# Sprint 4.2 — Client Selection And Backend Contract Parity

- Support `HTTPClient`, `SQLClient`, and `CLIReader` behind one stable CLI

## Required Work

- Define the interaction between `dolt.client` and `--dolt-dir` explicitly.
  Preserve backward compatibility by treating `--dolt-dir` as a CLI-reader
  selector when no explicit client is supplied, and reject conflicting
  combinations with a typed `invalid_args` error.
- Define the exact precedence and test it as a matrix:
  explicit `--client`, environment override, file config, compatibility
  inference such as `--dolt-dir`, then documented default.
- Implement the DoltHub HTTP client required by the requirements and normalize
  its success and failure behavior to match SQL and CLI-backed clients.
- Ensure write-path admin commands reject `http` with `unsupported_backend`
  instead of attempting a hidden fallback.
- Add deterministic client-selection precedence and test it.
- Build shared conformance coverage so equivalent operations produce equivalent
  top-level success and error contracts across all three client modes.

## Implementation Notes

The dev should not invent transport-specific CLI behavior. Equivalent commands
must agree at the top level and differ only inside structured details:

```json
{
  "ok": false,
  "error": {
    "code": "backend_unavailable",
    "details": {
      "client": "cli",
      "cause_code": "dolt_binary_missing"
    }
  }
}
```

Recommended test seams:
- `httptest.Server` for `HTTPClient`
- adapter-level fake or harnessed MySQL endpoint for `SQLClient`
- injected command runner or fixture-backed subprocess shim for `CLIReader`
- one shared conformance suite run against all three transports

## Acceptance Criteria

- The CLI can select `http`, `sql`, or `cli` explicitly without changing the
  public JSON schema.
- Equivalent backend failure classes map to the same top-level CLI error codes.
- Adapter-level simulator or harness coverage exists for each client mode.
- Live backend verification remains manual or AI-driven integration testing
  only and is not part of normal CI.
- Admin write-path commands fail deterministically with `unsupported_backend`
  when `http` is the effective client.
