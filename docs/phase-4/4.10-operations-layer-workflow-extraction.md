# Sprint 4.10 — Operations Layer: Install, Upgrade, Uninstall Workflow Extraction

## Goal

- Move install, upgrade, and uninstall workflow policy out of Cobra command handlers and into `src/pkg/operations`, satisfying the MB-001 and MB-006 module boundary requirements.

## Hard Dependencies

- Sprint `4.9` complete.

## Normative References

- Requirement: `MB-001`
- Requirement: `MB-006`
- Requirement: `REQ-005`
- ADR: `ADR-0004`

## Exact Targets

- `src/pkg/operations/`
- `src/cmd/install.go`
- `src/cmd/upgrade.go`
- `src/cmd/uninstall.go`

## Required Work

- Extract the install workflow from `src/cmd/install.go` (scope-loop, multi-scope aggregation, error envelope construction) into a new function or set of functions in `src/pkg/operations/install.go`. The Cobra handler becomes a thin binding: parse flags, call operations, format output.
- Extract the upgrade workflow from `src/cmd/upgrade.go` into `src/pkg/operations/upgrade.go`. The Cobra handler becomes a thin binding.
- Extract the uninstall workflow from `src/cmd/uninstall.go` into `src/pkg/operations/uninstall.go`. The Cobra handler becomes a thin binding.
- Cobra handlers in `src/cmd/` must contain only: flag parsing, calling the extracted operation function, and passing the result to the output formatter. No business logic (scope decisions, error classification, retry semantics) in the handler.
- Ensure all existing tests continue to pass. Add or update tests in `src/pkg/operations/` to cover the extracted workflow logic directly.

## Implementation Notes

- The operations layer already exists at `src/pkg/operations/` with readback/validation helpers from Sprint 4.3. Extend it with install, upgrade, uninstall.
- The operation functions should accept typed inputs (not cobra.Command or flag sets) and return typed results. No cobra imports in pkg/operations.
- The JSON error contract (retryable, suggested_action, cause_code, operation) is populated in `src/cmd/json_errors.go` today. Keep error formatting in the cmd layer; the operations layer returns typed Go errors.
- Sprint 4.9 uninstall atomicity changes should already be on the branch — build on that corrected implementation.

## Non-Goals

- Do not change the JSON output format or error contract — that is a cmd-layer concern.
- Do not move the output formatter into pkg/operations.
- Do not extract flag parsing — that stays in cmd.

## Acceptance Criteria

- `src/pkg/operations/install.go` exists and contains the install scope-loop and multi-scope aggregation logic.
- `src/pkg/operations/upgrade.go` exists and contains the upgrade workflow logic.
- `src/pkg/operations/uninstall.go` exists and contains the uninstall workflow logic.
- `src/cmd/install.go`, `src/cmd/upgrade.go`, `src/cmd/uninstall.go` handlers contain no package-management business logic — only flag parsing, operation call, and output formatting.
- No `cobra` imports in `src/pkg/operations/`.
- `go test ./src/pkg/operations/...` passes with coverage of the extracted workflow logic.
- `go test ./...` passes.
- `go test ./... -race` passes.
- `golangci-lint run ./...` passes.
- `git diff --check` passes.

- `go test ./src/cmd/...`
- `go test ./...`
- `go test ./... -race`
- `golangci-lint run ./...`
