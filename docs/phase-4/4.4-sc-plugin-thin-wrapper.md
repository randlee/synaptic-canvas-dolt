## Required Work

- Create the in-repo `sc:plugin` skill package.
- Define explicit natural-language to `sc --json` command mapping.
- Keep the skill implementation declarative: shell out to `sc --json`, parse
  only JSON, and never parse human-readable output or duplicate CLI business
  rules.
- Cover representative utterances for install, upgrade, uninstall, status,
  validate, and snapshot flows, including ambiguity and backend failures.
- Add fixture-backed verification for representative success and error cases.
- Document clearly that ATM/task-loop orchestration remains outside the skill.

## Implementation Notes

The skill should contain:
- one primary instruction file that defines scope and boundaries
- explicit examples of utterance-to-command mapping
- examples that preserve non-default `--branch`, `--version`, and `--scope`
  selections in generated commands

Representative mappings:

```text
"install team-lead from beta globally"
-> sc install team-lead --branch beta --scope global --json

"snapshot team-lead"
-> if installed in both scopes, return the CLI's ambiguous_target result and
   ask for an explicit scope rather than choosing one
```

## Acceptance Criteria

- Wrapper actions shell out to `sc` with `--json`.
- Wrapper verification covers success, ambiguity, backend failure, and
  corrective-error presentation.
- The wrapper does not create a second business-payload schema separate from
  the CLI contract.
- The wrapper does not absorb ATM polling, sprint loops, git orchestration, or
  team workflow control.
- The wrapper never parses human-readable CLI output.
