## Required Work

- Stage the `sc:plugin` skill payload update into a temporary directory and
  perform an atomic rename/move into `~/.claude/skills/sc-plugin/` only after
  a fully successful copy. This ensures that an interruption during the managed
  file copy leaves the existing installation intact rather than partially
  updated.
- Add failure-injection tests to `tests/installer/test_install.sh` and
  `tests/installer/test_install.ps1` that verify the old skill state is
  preserved if a simulated copy failure occurs mid-update.
- Update `docs/dolt-api.md` with the five-level client-selection precedence
  introduced in Sprint 4.2 (flag → env → project config → machine config →
  compiled default).
- Add an architecture note or ADR section to `docs/architecture.md` covering
  the installer managed/unmanaged boundary: what constitutes a managed file,
  what the installer must never touch, and how the boundary is enforced.

## Implementation Notes

On macOS/Linux, the atomic update can use `cp -r` to a `tmpdir` followed by
`mv` (rename) into the target path — a single `mv` within the same filesystem
is atomic on POSIX systems. On Windows, use `Move-Item -Force` after staging
to a temp path.

The failure-injection test can simulate a mid-copy failure by writing a
trap/hook that exits non-zero after the first managed file is written, then
asserting the destination tree matches the pre-update state.
