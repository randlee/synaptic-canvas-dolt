## Required Work

- Introduce a shared CLI-facing contract package for success envelopes, error
  envelopes, and command-specific JSON payloads so the CLI has one canonical
  machine schema family.
- Define the exact shared error-code family for MVP:
  `invalid_args`, `not_found`, `ambiguous_target`, `unsupported_backend`,
  `backend_unavailable`, `backend_auth_failed`, `confirmation_required`,
  `blocked`, `conflict`, `validation_failed`, and `internal_error`.
- Replace ad hoc `map[string]any` success payloads with typed response structs.
- Move JSON failure handling to the root execution boundary so bootstrap
  failures still render the standard JSON error envelope in `--json` mode.
- Define stable typed error codes with structured `details`,
  `suggested_action`, and retryability where automation needs it.
- Cover all current end-user commands in this sprint: `list`, `info`, `init`,
  `install`, `upgrade`, `uninstall`, `validate`, `status`, `scan`, `catalog
  update`, `config get`, `config set`, and `snapshot`.
- Add contract-focused tests that assert JSON success and failure shapes
  directly.

## Implementation Notes

Use a shared API package rather than command-local maps. The naming below is
illustrative, but the split should be concrete and reusable:

```go
type ErrorCode string

const (
    ErrorInvalidArgs        ErrorCode = "invalid_args"
    ErrorNotFound           ErrorCode = "not_found"
    ErrorAmbiguousTarget    ErrorCode = "ambiguous_target"
    ErrorUnsupportedBackend ErrorCode = "unsupported_backend"
    ErrorBackendUnavailable ErrorCode = "backend_unavailable"
    ErrorBackendAuthFailed  ErrorCode = "backend_auth_failed"
    ErrorConfirmationNeeded ErrorCode = "confirmation_required"
    ErrorBlocked            ErrorCode = "blocked"
    ErrorConflict           ErrorCode = "conflict"
    ErrorValidationFailed   ErrorCode = "validation_failed"
    ErrorInternal           ErrorCode = "internal_error"
)
```

Root-level execution should decide whether to render a JSON error envelope
before Cobra command business logic runs so config, branch, and client bootstrap
failures do not escape as raw stderr prose.

## Acceptance Criteria

- All end-user commands return typed JSON success envelopes in `--json` mode.
- Failures that occur before command business logic still return the standard
  JSON error envelope when `--json` is set.
- Typed error categories cover invalid args, ambiguous targets, backend
  failures, local-modification blocks, confirmation-required states, and
  internal failures.
- Every command in the Phase 3/4 end-user surface returns a typed response
  object and no command emits `map[string]any` payloads in `--json` mode.
- Command-family tests assert JSON schema shape across success and failure
  paths.
