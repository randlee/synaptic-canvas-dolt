# Sprint 6.1 — sc dolt Pass-Through Commands

## Goal

- Add an `sc dolt` subcommand family that forwards directly to the local `dolt` CLI so users can discover and use clone/pull/push/status-style Dolt workflows through the Synaptic Canvas entry point.
- Keep the feature thin: preserve native Dolt semantics, surface missing-CLI guidance clearly, and avoid creating a second database-management model.

## Hard Dependencies

- Phase 5 MVP release work complete.
- Dolt CLI install guidance already documented or available through Synaptic Canvas package docs.

## Normative References

- Requirement: `REQ-006`
- Requirement: `REQ-003`
- Requirement: `REQ-005`
- ADR: `ADR-0001`

## Exact Targets

- `src/cmd/dolt.go`
- `src/cmd/root.go`
- `docs/project-plan.md`
- `docs/synaptic-canvas-cli.md`

## Required Work

- Add `sc dolt <args...>` as a thin pass-through to the local `dolt` CLI.
- Fail clearly when `dolt` is not installed and point users to install guidance instead of silently degrading.
- Preserve native Dolt argument and error behavior rather than translating it into a second command model.
- Document common discovery flows such as clone, pull, push, and status through `sc dolt`.

## Implementation Notes

- This is a convenience UX layer for users who know `sc` but not Dolt.
- The wrapper should forward arguments with minimal interpretation.
- Do not hide real Dolt failures or reinterpret them as Synaptic Canvas business rules.

## Non-Goals

- Do not replace native Dolt workflows.
- Do not add Synaptic Canvas-specific state management around forwarded Dolt commands.

## Acceptance Criteria

- `sc dolt` forwards arbitrary supported arguments to the installed `dolt` CLI.
- Missing `dolt` is surfaced with a clear install/remediation message.
- Docs describe the feature as a thin convenience wrapper, not a second database model.
