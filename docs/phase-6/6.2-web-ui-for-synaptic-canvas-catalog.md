# Sprint 6.2 — Web UI For Synaptic Canvas Catalog

## Goal

- Plan and implement a web UI that reads Synaptic Canvas package data from DoltHub and presents the catalog of skills and packages in a browsable site.
- Establish the frontend architecture, data access model, and deployment shape for an Astro or similar static-first framework.

## Hard Dependencies

- Phase 5 MVP release work complete.
- Readable DoltHub package catalog with stable package metadata fields.

## Normative References

- Requirement: `REQ-006`
- Requirement: `REQ-003`
- Requirement: `REQ-005`
- ADR: `ADR-0001`
- ADR: `ADR-0002`

## Exact Targets

- `docs/project-plan.md`
- `docs/phase-6/6.2-web-ui-for-synaptic-canvas-catalog.md`

## Required Work

- Choose the frontend stack, with Astro as the starting candidate unless another static-first framework is justified.
- Define how the UI reads package data from DoltHub, including build-time versus runtime fetch behavior.
- Define the initial browsing experience for packages, skills, dependency/install guidance, and package metadata.
- Plan the deployment model and cache/update strategy for catalog freshness.

## Implementation Notes

- The first milestone is planning and architecture, not full product parity with the CLI.
- The UI should start as a read surface over DoltHub catalog data.
- Keep the framework decision explicit; Astro is preferred unless requirements push elsewhere.

## Non-Goals

- Do not make the first UI milestone a full package-management client.
- Do not duplicate all CLI behavior in the browser.

## Acceptance Criteria

- The sprint plan defines the frontend stack decision, DoltHub read path, initial UX scope, and deployment model.
- The plan keeps the first milestone focused on catalog browsing rather than full browser-side package management.
