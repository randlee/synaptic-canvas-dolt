# Sprint 5.5 Launch-Terminal Merge Decision

## Decision

- `sc-launchpad` and `sc-launch-term` shall be merged into one Synaptic Canvas package before implementation continues.
- The merged package shall provide multiple launch skills over shared infrastructure rather than keeping two partially overlapping packages.

## Scope Of The Merged Package

- One package contains the launch skills for:
  - Claude Code
  - Codex CLI
  - Gemini CLI
- The package may also carry background-agent variants where the shared infrastructure is the same.

## Rationale

- The two source packages share the same package boundary in practice:
  - terminal-launch infrastructure
  - external CLI dependency handling
  - install and troubleshooting guidance
  - export expectations for traditional marketplaces
- Keeping them split would duplicate:
  - dependency metadata
  - install-and-troubleshooting guidance
  - validation rules
  - future Synaptic Canvas automation guidance
- The merged package better matches the Phase 5 package-expansion goal of proving one shared-infrastructure package can expose multiple skills without inventing separate package-management rules.

## Install And Troubleshooting Rule

- The merged package shall preserve standard non-Synaptic-Canvas install guidance for each external CLI.
- Vendor-managed CLI installation steps shall point to the official upstream install sources rather than copying volatile instructions into the package.
- The package shall add a short Synaptic Canvas section covering:
  - `sc install <package>`
  - `sc upgrade <package>`
  - `sc uninstall <package>`

## Follow-Up Constraints

- This decision does not require the merged package implementation to be completed inside Sprint 5.5.
- Sprint 5.5 must treat the merge topology as decided so later implementation and QA do not have to guess about package boundaries.
