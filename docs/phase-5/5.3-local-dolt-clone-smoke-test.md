# Sprint 5.3 — Local Dolt Clone Smoke Test

## Goal

- Prove the first imported package works end-to-end against a local clone of the package database.
- Exercise the native `dolt` CLI workflow directly for clone, pull, and push operations.
- Verify both local-scope and global-scope package installs against the local-clone backend.

## Hard Dependencies

- Sprint 5.2 produced a clean `claude-history` package ready for import.
- `dolt` CLI is installed locally and can clone the target package database.
- A writable test branch or test database is available for local-clone verification.

## Exact Targets

- Local clone of the package database created with `dolt clone`
- Package rows for the imported `claude-history` package in the local clone
- Project-local install target under a clean test repository
- Machine-global install target on the test workstation

## Required Work

- Import the normalized `claude-history` package into a test catalog branch that can be cloned locally.
- Clone the package database locally with the native `dolt` CLI.
- Verify the imported package exists in the local clone before running end-user commands.
- Run `list`, `info`, `install`, `status`, `validate`, `upgrade`, `uninstall`, and reinstall flows against the local-clone backend through the public `sc` CLI with `--json`.
- Exercise both project-local scope and machine-global scope installs and confirm the status table reflects both scopes correctly.
- Capture evidence for command outputs, installed files, validation severity, and uninstall cleanup.

## Implementation Notes

- Use the same package content that will later be exercised against DoltHub so the comparison is meaningful.
- Use the native `dolt` CLI directly for clone and synchronization work. `sc dolt` is a later Phase 6 convenience feature, not an MVP dependency.
- Do not bypass the public CLI contract with ad hoc local SQL or filesystem shortcuts during smoke validation. Product proof must run through `sc`.
- Keep the test repository clean enough that install/uninstall residue is obvious.

## Non-Goals

- Do not treat the local-clone smoke test as a substitute for DoltHub testing.
- Do not broaden the first smoke pass to every candidate package.
- Do not hide backend-selection details from the evidence. The proof must show the local-clone path explicitly.

## Acceptance Criteria

- The imported package is visible in a local Dolt clone created with the native `dolt` CLI.
- Local-scope install, global-scope install, `status`, `validate`, `upgrade`, `uninstall`, and reinstall flows pass against the local-clone backend.
- Evidence shows the same package version/branch/shape that was imported in Sprint 5.2.
- Any failure-path or cleanup issue is recorded explicitly rather than deferred as an informal note.

## Required Validation

- `dolt clone <test-remote> <local-clone-dir>`
- `dolt -C <local-clone-dir> sql -q "show tables"`
- `(cd src && go test ./...)`
- `(cd src && go test ./... -race)`
- `(cd src && golangci-lint run ./...)`
- `git diff --check`

## Completion Report Requirements

- Record any local-clone workflow issues encountered and the exact fixes completed during Sprint 5.3.
- Record backend, scope, install-state, or validation issues found during the smoke pass even if they are fixed immediately.
- Record any unresolved local-clone gaps as explicit follow-up items for later sprints instead of treating the smoke pass as informally “close enough.”
