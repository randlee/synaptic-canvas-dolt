# Sprint 5.6 — Phase-5 Hardening And Follow-Up Closure

## Goal

- Consume the issues and follow-up items recorded in Sprint `5.1–5.5`.
- Close the remaining Phase 5 items that still belong in MVP scope.
- Rerun the critical release and product smoke matrix after fixes.
- Produce the final Phase 5 readiness report.

## Hard Dependencies

- Sprint `5.1–5.5` completion reports exist and include issues encountered, fixes completed, and deferred follow-up items.
- The first import candidate and the expansion package set have already gone through the documented local-clone and DoltHub smoke paths.
- Release-pipeline work from Sprint 5.1 is stable enough to support a final validation rerun after fixes.

## Required Work

- Consolidate the issues and follow-up items recorded by Sprint `5.1–5.5` completion reports into one ordered hardening list.
- Fix the MVP-scope issues that remain open from earlier Phase 5 sprints.
- Triage every unresolved item through the documented gate in `docs/phase-5/process-qa-triage.md` before deciding whether it is fixed in Sprint 5.6 or deferred.
- Defer non-MVP items explicitly instead of leaving them mixed with the MVP hardening queue.
- Rerun the critical validation path after fixes:
  - release validation path
  - first-package import path
  - local-clone smoke path
  - DoltHub smoke path
- Produce the final Phase 5 readiness report listing:
  - issues encountered
  - fixes completed
  - validation reruns performed
  - remaining deferred items and rationale

## Implementation Notes

- Sprint 5.6 is the consumer of the issue-recording rules added to earlier Phase 5 sprints. It exists to prevent follow-up items from becoming informal backlog drift.
- The final readiness report target path is `docs/phase-5/phase-5-readiness-report.md`.
- Keep the rerun set focused on the critical product proof. The point is to show the post-fix state, not to create an open-ended exploratory cycle.
- If a larger issue cannot be closed inside Phase 5 without broadening MVP scope, defer it explicitly into a later phase with rationale.

## Non-Goals

- Do not reopen already-closed work without a concrete regression or blocker.
- Do not turn Sprint 5.6 into an unbounded “cleanup everything” phase.
- Do not defer MVP-scope blockers without naming them in the final readiness report.

## Acceptance Criteria

- A detailed Sprint 5.6 plan exists in `docs/phase-5/5.6-phase-5-hardening-and-follow-up-closure.md`.
- MVP-scope follow-up items from Sprint `5.1–5.5` are either fixed or explicitly deferred with rationale.
- Critical validation and smoke evidence is rerun after fixes rather than relying only on pre-fix evidence.
- The final Phase 5 readiness report at `docs/phase-5/phase-5-readiness-report.md` explicitly lists issues encountered, fixes completed, remaining deferred items, and their triage disposition.
