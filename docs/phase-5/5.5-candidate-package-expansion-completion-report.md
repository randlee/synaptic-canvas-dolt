## Blocking Findings

### 1. Install-time aggregate SHA verification still uses installed destination paths

- `sprint-report` install failed with:
  - `aggregate sha mismatch for sprint-report`
- `claude-history` regression install failed with:
  - `install failed for all selected scopes`
  - project-scope failure `aggregate sha mismatch for claude-history`
- Concrete implementation path:
  - importer package SHA is computed from catalog file `DestPath` values that represent stable package doc paths during import in [src/pkg/importer/importer.go](/Users/randlee/Documents/github/synaptic-canvas-dolt-worktrees/feature/p5-s5-package-expansion/src/pkg/importer/importer.go:118)
  - install recomputes the aggregate from rendered install destination paths in [src/pkg/installer/installer.go](/Users/randlee/Documents/github/synaptic-canvas-dolt-worktrees/feature/p5-s5-package-expansion/src/pkg/installer/installer.go:165)
  - aggregate hashing sorts and hashes `DestPath:SHA` pairs exactly as provided in [src/pkg/integrity/aggregate.go](/Users/randlee/Documents/github/synaptic-canvas-dolt-worktrees/feature/p5-s5-package-expansion/src/pkg/integrity/aggregate.go:10)
- Result:
  - imported package aggregate SHAs are keyed to package doc paths
  - install verification is keyed to runtime install paths
  - any package with relocated install targets fails install-time aggregate validation
