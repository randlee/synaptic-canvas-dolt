# Sprint 5.1 — Release Pipeline

## Goal

- Define and implement an MVP release pipeline that is explicit about the supported archive matrix, validates GoReleaser configuration before tags are cut, and publishes GitHub release artifacts without hiding package-manager gaps.
- Keep MVP release scope unambiguous by documenting Homebrew prerequisites and Winget deferral while preserving tag-triggered publication for the shipped release surface.

## Hard Dependencies

- Phase 4 merged into `develop` and `integrate/phase-5` is current with that baseline.
- GoReleaser is available in CI and in maintainer environments used for non-publishing dry runs.
- Homebrew tap access for `randlee/homebrew-tap` is provisioned before the first tagged publish.

## Required Work

- Create a non-publishing release-validation workflow on pull requests and pushes that runs `goreleaser check` against the repository release config; keep the tagged publish workflow focused on actual release publication.
- Update `.github/workflows/release.yml` so tagged publication remains the only publish path, and document or implement non-blocking behavior for Homebrew tap update failures so GitHub release artifacts are still published.
- Update `.goreleaser.yml` to codify the explicit release archive matrix in priority order: primary `darwin/arm64`, `windows/amd64`, `linux/amd64`; secondary `darwin/amd64`, `windows/arm64`, `linux/arm64`.
- Treat `windows/arm64` as included in MVP scope as a secondary archive target. The deferred item is Winget publication, not the underlying Windows ARM64 release artifact.
- Winget publication is enabled in `.goreleaser.yml` (standalone fix, PR #55). Sprint 5.1 does not change winget enablement. Update `docs/synaptic-canvas-cli.md` to state that winget submission occurs on every release tag; Microsoft approval requires a publisher certificate (tracked by gh issue `#54`) — once the certificate is supplied, no further config changes are needed.
- Update `docs/synaptic-canvas-cli.md` so the distribution section and CI workflow section match actual MVP behavior: Homebrew plus release archives are active, `go install` remains available, and Winget publication is deferred.
- Update `docs/project-plan.md` Phase 5 summary so it references this sprint plan, names the explicit release matrix, and reflects the dry-run validation plus Homebrew prerequisite/failure policy.

## Implementation Notes

- `amd64` is the Go/GoReleaser architecture name for x64/x86_64. The plan should use both the Go names and the human-readable platform labels so reviewers do not confuse `amd64` with a legacy-only target.
- Replace vague phrases such as “all supported platforms” with the explicit matrix. MVP includes `windows/arm64` as a secondary release archive target; only Winget publication remains deferred.
- Preferred CI shape: leave `.github/workflows/release.yml` tag-triggered for publishing, and add `.github/workflows/release-validate.yml` for PR/push validation. If the implementation instead extends an existing workflow, it must still run `goreleaser check` before tag time.
- Homebrew publication requires `HOMEBREW_TAP_TOKEN` with at least `contents:write` on `randlee/homebrew-tap`. The implementation must document this prerequisite and treat missing or failed tap updates as a warning path that does not block the GitHub release itself.
- Winget publication is blocked pending publisher registration and is tracked by gh issue `#54`. Sprint 5.1 must describe it as deferred rather than silently retaining stale documentation.
- If the implementation needs to mention the generated tap formula path, reference it as external output in `randlee/homebrew-tap/Formula/sc.rb`; do not imply that the formula source lives in this repository unless a mirrored artifact is intentionally added.

## Non-Goals

- Do not disable Winget publication — it is already enabled via PR #55; Sprint 5.1 only updates documentation to reflect submission-plus-cert-required status.
- Do not broaden MVP scope beyond the documented release archive matrix and existing installer/runtime boundaries.
- Do not move ATM orchestration, team workflow policy, or package-management business logic into release scripts or `sc:plugin`.

## Acceptance Criteria

- A detailed Sprint 5.1 plan exists in `docs/phase-5/5.1-release-pipeline.md` and the Phase 5 summary in `docs/project-plan.md` points to it.
- PR/push validation runs `goreleaser check` without requiring a tag, and the tagged publish workflow remains the only publishing path.
- The release configuration explicitly documents the MVP archive matrix with primary targets `darwin/arm64`, `windows/amd64`, `linux/amd64` and secondary targets `darwin/amd64`, `windows/arm64`, `linux/arm64`.
- Sprint docs and release docs state explicitly that `windows/arm64` is included in MVP as a secondary archive target rather than being silently omitted or ambiguously deferred.
- `docs/synaptic-canvas-cli.md` accurately reflects that winget submission occurs on every tag; Microsoft approval requires a publisher certificate (gh issue `#54`); no code change is needed once the cert is supplied.
- Sprint documentation specifies `HOMEBREW_TAP_TOKEN`, the required `contents:write` permission on `randlee/homebrew-tap`, and the non-blocking behavior when tap update fails.
- `git diff --check` passes for the release-planning changes.
