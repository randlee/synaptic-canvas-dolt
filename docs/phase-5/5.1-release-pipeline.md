# Sprint 5.1 — Release Pipeline

## Goal

- Define and implement an MVP release pipeline that is explicit about the supported archive matrix and validates GoReleaser configuration before tags are cut.
- Keep MVP release scope unambiguous by documenting Homebrew prerequisites and Winget certificate requirement while preserving tag-triggered publication for the shipped release surface.

## Hard Dependencies

- Phase 4 merged into `develop` and `integrate/phase-5` is current with that baseline.
- PR #55 (`feature/homebrew-publish`) merged into `develop`: Winget publication enabled in `.goreleaser.yml`; `windows/arm64` added to release matrix; token fallbacks removed from `release.yml`.
- GoReleaser is available in CI and in maintainer environments used for non-publishing dry runs.
- Homebrew tap access for `randlee/homebrew-tap` is provisioned before the first tagged publish.

## Required Work

- Create a non-publishing release-validation workflow (`.github/workflows/release-validate.yml`) on pull requests and pushes that runs `goreleaser check` against the repository release config; keep the tagged publish workflow focused on actual release publication.
- Update `.github/workflows/release.yml` to document the non-blocking behavior for Homebrew tap update failures so GitHub release artifacts are still published if the tap update fails.
- Update `docs/synaptic-canvas-cli.md` so the distribution section and CI workflow section match current `develop` state: Homebrew and release archives active, `go install` available, Winget submission occurs on every release tag and requires a publisher certificate from Microsoft (gh issue `#54`) before the package appears in the winget catalog, `release-validate.yml` is planned under Sprint 5.1 rather than already shipped.
- Update `docs/project-plan.md` Phase 5 summary so it references this sprint plan, names the explicit release matrix, and reflects the dry-run validation and Homebrew prerequisite/failure policy.

## Implementation Notes

- `amd64` is the Go/GoReleaser architecture name for x64/x86_64. Use both the Go names and the human-readable platform labels so reviewers do not confuse `amd64` with a legacy-only target.
- **Release matrix (already codified in `.goreleaser.yml` by PR #55):** Primary: `darwin/arm64`, `windows/amd64`, `linux/amd64`. Secondary: `darwin/amd64`, `windows/arm64`, `linux/arm64`. Sprint 5.1 does not change the matrix — document it accurately.
- **Winget (already enabled by PR #55):** GoReleaser submits a PR to `microsoft/winget-pkgs` on every release tag via `randlee/winget-pkgs`. Microsoft review requires a publisher certificate (gh issue `#54`). Once the certificate is supplied, no further config changes are needed. Sprint 5.1 does not change winget config — document it accurately.
- Preferred CI shape: leave `.github/workflows/release.yml` tag-triggered for publishing, and add `.github/workflows/release-validate.yml` for PR/push validation running `goreleaser check`.
- Homebrew publication requires `HOMEBREW_TAP_TOKEN` with at least `contents:write` on `randlee/homebrew-tap`. Treat missing or failed tap updates as a warning path that does not block the GitHub release itself.
- If the implementation needs to mention the generated tap formula path, reference it as external output in `randlee/homebrew-tap/Formula/sc.rb`; do not imply that the formula source lives in this repository.

## Non-Goals

- Do not change Winget publication config — already enabled by PR #55; cert supply is the only remaining step (tracked in gh issue `#54`).
- Do not change the release archive matrix — already correct in `.goreleaser.yml` after PR #55.
- Do not broaden MVP scope beyond the documented release archive matrix and existing installer/runtime boundaries.
- Do not move ATM orchestration, team workflow policy, or package-management business logic into release scripts or `sc:plugin`.
